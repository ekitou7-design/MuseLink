## 4. 常见问题总结

1. `description` 安全但过于模板化：优点是没有明显编造；缺点是重复字段，缺少“可能反映”“可作为理解……的材料之一”等解释性谨慎表达。
2. `shortIntro` 太像字段摘要：适合作为占位，不适合作为正式文案。
3. `馆藏精品` 使用过多：抽样中石印、生活用品、铁器、铜器、纸本文献都容易落入泛标签。
4. 铜器标签偏弱：材质含铜只进入 `materialTags`，但很多铜器没有进入 `金属工艺` 或 `青铜器/礼器/兵器` 等主题。
5. 题名与结构化字段存在冲突或信息差：如 `春秋战国曲刃青铜短剑` 题名含时代但 period 缺失；`清白地堆花鼻烟壶（无盖）` 类别瓷器但材质玻璃。
6. 标点清洗不足：若备注或尺寸已有句号，description 容易生成 `。。`。
7. 文献类主题不足：如地契、手札、笺纸应增加“档案文献”“社会生活”“文房书写”等主题候选。
8. 版权和来源仍是硬缺口：`sourceUrl` 为 `暂无信息`，正式 RAG 引用时无法回链权威来源。

## 5. 需要调整的生成规则

建议下一轮只改脚本规则，不直接手改数据。

1. 增加 `needsHumanReview` 或 `reviewFlags`：
   - 字段冲突：类别为瓷器但材质为玻璃。
   - 题名含朝代但 period 缺失。
   - 题名含缺字符号 `□`。
   - 尺寸疑似异常或单位缺失。
2. 改进 `description`：
   - 保留结构化事实。
   - 增加谨慎表达，如“可作为理解相关材质工艺、器物类型或馆藏体系的材料之一”。
   - 避免把字段重复两遍。
3. 改进标签规则：
   - `category` 含铜器、金属器、武器，或 `materialTags` 含铜/铁/银/金时，可补 `金属工艺`，但最好区分置信度。
   - `category` 为生活用品类时补 `日用器物`。
   - `category` 为书法/绘画时当前规则可保留。
   - 地契、手札、笺、图册等补 `档案文献`、`书写文化` 或 `社会生活`。
   - 石印、印信、符牌补 `印章篆刻` 或 `文房清供`。
4. 改进 `curatorNote`：
   - 从“材质工艺”扩展到“器物功能/文献类型/艺术门类”。
   - 避免对地契这类文献仅写“纸质工艺”。
5. 改进文本清洗：
   - 去除重复句号。
   - 对 `暂无信息` 字段减少自然语言展开，避免 RAG 噪声。
6. 不建议从题名直接覆盖正式字段：
   - 可以生成低置信标签或 `reviewFlags`，例如“题名含春秋战国，时代字段待核”。
   - 不应直接把题名推断写入 `period`。

## 6. 是否建议进入 RAG 测试

建议进入小规模 RAG 测试，但不建议进入正式知识库或面向用户的讲解生产。

可测试范围：

- 向量检索召回：按文物名称、朝代、类别、材质、标签检索。
- metadata 过滤：按 `dynasty`、`category`、`regionTag`、`cultureTags`、`themeTags` 过滤。
- 文物推荐原型：测试同朝代、同材质、同主题的召回效果。

不建议测试范围：

- 不建议作为最终讲解文案。
- 不建议让模型基于当前 description 生成历史故事。
- 不建议把 `artifact-relation-seeds.json` 当作已确认知识图谱事实。

结论：当前数据达到“RAG 技术验证可用”的最低线，但未达到“正式内容上线”的质量线。进入 Dify / FastGPT / RAGFlow 前，建议先调整自动生成规则，再重新生成 AI-ready 数据并复审。
