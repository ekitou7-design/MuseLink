# src/services 文件夹说明

这个文件夹放的是前端里比较「业务化」的能力。

目前最重要的是智能策展和相关文物推荐。

## curatorService.ts 是做什么的？

它负责这些事：

- 根据用户输入的主题，生成一个展陈草案
- 从文物库里挑出比较相关的文物
- 给文物详情页推荐相似或相关文物
- 如果以后接入真正的大模型服务，也会从这里发起请求

## 当前知识库能支撑什么

`curatorService.ts` 已经会使用后端 `/api/rag/search` 从知识库里找候选文物。当前检索模式是本地关键词排序，数据来源优先使用 `data/imported-artifacts.json` 的 226 件导入文物。

在没有外部 AI 或向量数据库时，它也能基于本地规则完成：

- 主题展陈草案生成
- 候选文物挑选
- 同馆藏、同时代、同材质、同文化等相关文物推荐

更完整的 RAG 文档和关系候选已经离线生成在 `data/rag/artifacts-rag-documents.v2.jsonl` 和 `data/artifact-relation-seeds.v2.json`，可作为后续接入外部知识库平台的材料。

## 现在必须接 AI 接口吗？

不必须。

项目现在有本地规则，即使没有外部 AI 密钥，也可以生成基础展陈草案。

如果以后要接入更强的 AI 服务，建议让后端或自建网关保存密钥，不要把密钥直接写在前端。

## 线上部署要注意什么？

智能策展会请求后端接口。

如果前端和后端分开部署，需要配置：

```text
VITE_API_BASE_URL=https://你的后端网址
```

如果使用 Cloudflare Pages Functions 代理，则配置：

```text
BACKEND_API_BASE_URL=https://你的后端网址
```

## 给非技术同学的理解

你可以把这里理解成 App 的「策展助手」。

页面负责展示按钮和输入框，这里负责根据输入内容整理展陈方案。
